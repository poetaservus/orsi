# Native cloud rollback reassessment

The reported third prompt followed project inspection and a managed npm server
start: `great. currently the first section animation is disabled, can you re-enable it?\`.
The reversal preflight required an explanation in assistant narration accompanying
the retry. Native cloud responses may contain only function calls, so the tool
contract had no reliable argument channel for that explanation. The required
post-rejection source read could also be refused after two ordinary reads of the
same revision.

Both text-editing tools now expose an optional `reversal_reason`, bounded to
1,000 characters. The first reversal rejection names that argument and renews
only its target's source-read allowance. A retry still needs a complete read
received after rejection, matching source bytes and the identified earlier
revision, a nonblank explanation, and ordinary exact-call approval. Existing
assistant explanations remain supported. Changing explanation or digest arguments
does not create another rollback allowance.

A real three-prompt replay exposed a further premature stop: after one justified
rollback, the model proposed its earlier unsuccessful static value again.
That second rollback remains blocked without approval or execution. Once per
target, the rejection permits a fresh complete read and diagnosis leading to a
new file revision. A missing/incomplete/same-batch read or another return to a
tried revision still stops the turn. This does not renew mutation, project-check,
failure, model-request or overall work budgets. Subsequent novel edits retain
their existing approval and verification rules.

Previously recorded cloud edit calls lack the new optional argument. History
validation uses their original schema for that field only, preserving the raw
provider evidence and matching every original argument, call ID and settled
result. Newly generated calls still use the current strict schema. Tampered
evidence containing an explanation absent from its settled transcript is rejected.

The three-prompt replay also established that `in_view` could undo an explicitly
requested scroll: Playwright centered a partially visible hero, resetting the
scroll-driven animation before capture. Inspection now preserves the scroll
position when the target already intersects the viewport. An offscreen target
is still brought into view, then checked after application scroll handlers run
and again at capture time. The browser contract describes this behavior and
retains the requirement to review screenshot pixels for visual correctness.

Production prompts, routing, sampling, context policy, accepted model profiles,
user settings and the user's website are unchanged.

## Qualification

Focused qualification passed 236 checks covering native file edits/writes,
strict cloud requests through the actual SDK with a mock HTTP transport,
historical chat replay, denied approval, fresh reads, bounded repeated calls,
one rollback, and diagnosis into a new revision. The new required-read regression
failed on the starting main; the old-history compatibility and cycle-diagnosis
regressions also failed before their respective corrections.

Browser qualification passed 63 checks with one unavailable host symlink skip.
The actual Chromium regression demonstrated a 400-pixel scroll being reset to
zero before the fix and preserved afterward. Existing intro-lock, offscreen
navigation, model readiness, preview-error, pixel-delivery and process-ownership
checks still pass. Overlapping focused groups are not added together.

The unchanged default cloud profile (`gpt-6-luna`) completed the user's three
prompts in the same conversation: project summary, managed server start, then
animation re-enablement. Only the fixture path and preview port were substituted
to isolate the disposable website from the user's files and running server.
All three completion reviews were ready, across 37 model requests and 22
cumulative screenshot inputs. The third turn recovered from two unsuccessful
browser attempts and obtained three passing inspections; failed attempts are
retained rather than counted as passes. Its four edits and two builds completed.
All five recorded owned process IDs were gone afterward, managed shell sessions
were released, and the original website source hash was unchanged.

Independent inspection of the final disposable website passed at the initial
hero, after a 100-pixel hero scroll, and at the model section. Screenshot pixels
were reviewed: the scrolled hero displayed the logo and the model section
displayed the 3D device. The initial zero-progress hero was blank as expected.
All three inspection process trees were released. These observations verify
the sampled states, not every animation frame or possible model decision.

Earlier live attempts remain separate: one harness run lost a manual approval
and timed out; a completed replay exposed the premature second-reversal stop;
another correctly reported incomplete work when inspection reset its scroll.
An intermediate independent browser check preserved scrolling but failed its
locator timeout under load. The final successful replay did not exercise a
rollback; native SDK and runtime regressions cover the rollback and cycle
diagnosis paths, and an earlier live replay executed the justified rollback.
Authorized replay details and screenshots remain in ignored `state/`; baseline
summaries contain counts and fixed status labels rather than source, chat or keys.

The first completed full-suite run found three old native cloud fixtures missing
the newly optional strict-wire argument (3 failed, 3,450 passed, 61 skipped).
Their nullable field was added without changing acceptance prompts or assertions;
all 23 checks in the two affected test files then passed. An earlier full run
was interrupted during diagnosis and is not counted as complete.

The final native Windows full suite passed: **3,453 passed, 61 skipped, zero
failures or errors**, with 15 passing subtests, in 767.19 seconds. It used repository-local
`state/pytest-native-reversal-verified-full` as its temporary directory, with
JUnit and console reports under `state/native-reversal-verified-full.*`.
The skips are 51 opt-in live gates, eight unavailable host symlink cases and
two platform-specific checks. Skipped model/provider gates are not reported as
passed; the authorized default-cloud three-prompt replay above is the live gate
actually exercised. A content-free summary is retained at
`state/native-reversal-summary.json`.
