## Recovery and polling

The semantic-correction total remains diagnostic history. Enforcement now groups
argument recovery by capability and normalized target, with a separate bounded
completion-review streak. A successful corrected operation resolves its own
argument recovery; a read does not clear a failed edit. Relevant novel settled
mutations, a novel passing project check, and terminal owned-job observations
renew completion recovery. Repeated proposals without that progress still stop.
The existing three-rejected-edits guard, revision-cycle protection, identical-call
guards, approvals, cancellation, uncertain-outcome stops and overall turn budgets
remain in force. No additional provider request is made at an exhausted limit.

At a semantic stop, the executed prefix of a batch retains its call/result pairs,
the actual failure and remaining completion-review requirements. Later batch
calls do not dispatch. Required-call bookkeeping uses only that settled prefix.

An observed running owned shell session renews only its own status-poll allowance.
Status polling uses the existing `yield_time_ms` as a cancellable bounded wait
(default one second, maximum ten), returning earlier on process completion.
Failed and terminal observations do not grant unlimited identical calls. Native

## Receipt-bound completion review

The assessment remains a separate, tool-disabled model request. Its strict live
schema now includes evidence references and explicit claims. The runtime checks
current-turn identities, passing/stale project outcomes, terminal execution,
command success and exact screenshots actually sent to a responding native model
step. Attaching pixels to a transcript that stops before that step does not count
as delivery. Text fallback does not establish pixel delivery.

Running is process liveness. Claiming server readiness additionally requires a
current passing inspection of an existing preview in the same project; a temporary
server created and stopped by that inspection cannot qualify. The reviewer must
distinguish requested finite work from intentionally persistent servers and honor
requested skips and read-only reports. Missing or contradictory evidence is
corrected in assessment without replaying tools, within the existing format limit.
New durable outcomes validate these references against their original receipts.
Legacy assessments without evidence references remain readable.
