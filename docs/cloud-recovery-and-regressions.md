# Cloud inspection recovery and full regression repair

The reported animation request could stop after a rejected patch required a
fresh source read that the identical-call guard then prohibited. A real cloud
replay on the previous main reproduced that contradiction. Required recovery
reads now get a fresh allowance for that target. New inspection pixels also
permit source diagnosis within the inspected project, once per distinct
snapshot. Identical screenshots, unrelated reads, failed checks without pixels,
and unproven changes do not renew allowances. The three-rejected-edit guard,
mutation approvals, and overall work budgets remain in force.

One duplicate project check per turn can now return a `call_replayed` rejection
with earlier receipt IDs instead of immediately ending the whole turn. It starts
no process and requests no approval. The model can diagnose existing evidence,
make a concrete correction, or finish; another over-limit request still stops.
Other capability repetition and duplicate batches retain their existing guards.

Inspection validation now names rejected fields and their schema constraints
without echoing submitted values or unknown field names. Browser URL/PID rules
are explicit in the schema. Blocked edit completion retains the concrete tool
failure rather than replacing it with a generic source/approval message.
After a fresh read establishes that a patch is already present, subsequent
preflight rejections preserve diagnosis feedback instead of contradicting it
with another fresh-read-and-retry instruction. Failure budgets are unchanged.

The live website exposed a second runtime problem: a Vite development preview
could exhaust the 1 GiB job limit before serving its assets. Browser inspection
now has a trusted 4 GiB ceiling for its entire owned process tree. Other commands
retain the 1 GiB default, all jobs retain the 16-process ceiling and kill-on-close
ownership, and the model cannot set these limits. Native tests query the actual
Windows job limits. Inspection rechecks the final viewport target at capture
time, allowing deliberate navigation away from an earlier intro target while
still detecting a late scroll handler returning the final target offscreen.

The full baseline at `c9dddd3` had 246 failures, 3164 passes, 61 skips, and 15
passing subtests. Most failures came from legacy test doubles that supplied an
answer without the now-required completion assessment, outdated catalog/config
assertions, and shutdown fixtures that never selected the allocated startup
path. Those fixtures now explicitly implement their completed-candidate
assessments; negative completion tests remain explicit and unchanged. Source
recovery fixtures perform the required fresh read, historical chat assertions
allow the task-context system message, and UI waits release Python's GIL. The
fresh-node test clicks the radio indicator rather than empty widget space.
Shutdown fixtures always dispose their windows, preventing later vault tests
from inheriting leaked windows. Acceptance prompts, production prompts,
routing, sampling, context policy, model profiles, and user settings are unchanged.
The Git descendant-timeout fixture now has a bounded setup wait for its child
before starting the original one-second termination interval. It still tests
real native process termination and handle release, without treating Python
startup speed under load as a cleanup failure.

## Verification

completion checks. The feedback-specific run passed 72 checks. Earlier startup,

one unavailable host symlink skip; overlapping runs are not added together.

An earlier candidate full run was interrupted when live evidence exposed another

in 500.70 seconds. The skips comprise 51 opt-in model/provider/attachment/UI gates,
eight unavailable symlink checks and two platform-gated tests.
All deterministic runs use repository-local `--basetemp`; native Windows runs
use an unrestricted shell. Final evidence is retained under ignored
`state/cloud-recovery-final-verified.{log,xml}` and the content-free summary
`state/cloud-recovery-summary.json`.
Another pre-final full run had 3430 passes, one startup-race failure, 61 skips and 15
passing subtests. The Git timeout fixture was terminated before it created its
child; the bounded setup correction then passed all 60 Git installer tests.
These failed qualification runs remain recorded separately from the final run.

The real cloud check uses the existing accepted default profile and the unchanged
request `yes the animation was disabled temporary, can you re-enable it`.
It runs against a disposable copy of the website, with source reads and approved
changes confined to that copy. The existing API key is read in memory, never
written to reports or environment files. Synthetic conversation evidence remains
separate under ignored `state/`; baseline reports contain counts and fixed labels.
The user's website is not modified by qualification.

The successful real cloud replay used `gpt-6-luna`, completed after 42 requests,
made four settled edits, ran three successful production builds and seven browser
inspections, and received screenshots in model input. It corrected an intermediate
selector failure and continued after its completion assessment identified missing
hero visibility. Its final assessment was ready. Independent local captures of
the resulting source show the initial logo, changed scrolled appearance, and the
loaded 3D device in the second section. A two-second scrolled viewport timeout is
retained as failed evidence; the same check passed with the replay's five-second
allowance. All 11 recorded preview processes were independently confirmed gone.
An independent build of the final disposable source passed through the actual
project verification capability and released its owned process tree.
The final feedback-only branch was added after that replay and is covered by
focused regression checks; it was not exercised in that successful live path.

Earlier live failures remain recorded: required-source-read loop prevention,
an incomplete fixture missing its Vite metadata, preview memory exhaustion,
duplicate checks, and redundant edits. A successful replay does not certify
every stochastic model response. Optional local-model, other-profile, attachment,
legacy provider and platform/symlink gates remain separate from this cloud gate.
No profile selection, model capacity, sampling or credentials were migrated.
